# ASSIST-ADR-0001: Property-based testing для валидаторов и схем

| | |
|---|---|
| **Status** | Proposed |
| **Date** | 2026-10-24 |
| **Tags** | #assist #testing #pbt #fscheck-fluent #validators |

## Context

В репе два чистых C#-домена с поверхностью валидации: `AIGuiders.TomlSchema` (валидаторы форматов: RFC 5321 mailbox, RFC 3986 URI, лимиты октетов) и `McpToolManifest` (манифесты инструментов). Тесты — табличные `Theory` с придуманными кейсами.

Валидаторы — выгодная PBT-цель: у них есть свойства согласованности, и «валидатор не бросает на произвольной строке» — закон, который примеры не проверяют.

## Decision

1. Принять PBT на **FsCheck 3.6.0 (`FsCheck.Fluent`)** для чистых валидаторов и схем; CPM в репе нет — пин в тест-проекте.
2. Канонические свойства:
   - **Totality**: `∀ string: валидатор возвращает bool/Result, не бросает`;
   - **Согласованность со стандартом**: сгенерированные по RFC-грамматике строки валидны, заведомо ломающие (обрезка по лимиту октетов, недопустимые кодпоинты) — нет;
   - **Идемпотентность**: повторная валидация валидного — валидна; `TryParse∘Format` round-trip там, где есть форматер;
   - **Манифесты**: `load(render(manifest)) = manifest` на сгенерированных манифестах; неизвестные поля — диагностика, не исключение.
3. **Не мигрирует:** шаблоны `DotnetMcp.Templates` (файловые фикстуры), интеграции.
4. Шаблон дисциплины — GUIDERS-FSHARP-ADR-0010 (генераторы, доменные guard'ы, имена свойств = законы); здесь C#-поверхность (`Prop.ForAll`).

## Consequences

- Валидаторы перестают зависеть от фантазии автора таблицы кейсов.
- Генераторы RFC-подмножеств — одноразовая инвестиция, переиспользуемая всеми валидаторами пакета.
